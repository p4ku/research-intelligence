## 1. Context Resolution Hierarchy: Workspace, Run & Entity

In the Schwarz Research Intelligence (SRI) architecture, data entities have distinct lifecycles, scopes, and isolation boundaries:

### 1.1 Scope Boundaries
- **Workspace Scope**: The overarching research domain (e.g. *Quantum Computing*, *Solid-State Electrolytes*). All papers, extractions, upstream scrapers, and pipeline runs belong to a workspace.
- **Universal Paper Entity (`Paper`)**: Stores run-invariant bibliographic records (title, authors, publication date, DOI, arXiv ID, raw upstream `meta` JSON payload from arXiv XML / OpenAlex, canonical PDF storage binary, and extracted layout markdown).
- **Run-Scoped Evaluation (`PaperMetric` / `Extraction`)**: Stores intelligence generated by a specific pipeline execution:
  - Composite Signal Score and Python AST variable evaluation ledger.
  - Dual-stage screening decisions (*Abstract Screening* and *Full-Text Screening*) with full LLM rationales and cited evidence quotes.
  - Parameter extractions with confidence scores and evidence spans.

---

### 1.2 Run Context Binding & Fallback Hierarchy

> [!IMPORTANT]
> **Default Context Invariant (Missing `?run_id` ➔ Last Successful Run)**:  
> All views dependent on pipeline execution results (`/briefing`, `/papers`, `/papers/[id]`, `/ask`) accept an optional query parameter: **`?run_id=<uuid>`** (in the backend API: `?pipeline_run=<uuid>`).  
> **If the `?run_id` parameter is omitted (direct entry without context), the system ALWAYS resolves and returns data from the LAST SUCCESSFUL RUN (`last completed run`, strictly excluding `failed` and `aborted` states).**

The system evaluates run context via a strict three-tier resolution hierarchy:

1. **Primary (Explicit URL Query Parameter `?run_id=<uuid>`)**:  
   - When provided in the URL, it strictly locks the view to that specific historical run.  
   - Enables shareable permalinks, historical audit comparison, and citation of a specific Systematic Literature Review snapshot.
2. **Secondary (Session Context from TopBar `RunSelector`)**:  
   - If no parameter is present in the URL, the view synchronizes with the active run selected in the global top navigation bar.
3. **Tertiary (Hard Fallback to Last Successful Run)**:  
   - If a user navigates directly (e.g., pasting `/papers/[id]` from clipboard without parameters or session state), the system automatically queries the **last successful completed run** (`/api/pipeline-runs/?status=completed&ordering=-started_at`).

## 3. Query Parameter Specifications & Deep Linking

| Parameter Name | Target Route | Type | Description | Fallback Behavior When Omitted |
| :--- | :--- | :--- | :--- | :--- |
| `run_id` | `/briefing`, `/papers`, `/papers/[id]`, `/ask`, `/pipeline` | UUID | Locks view to the specified historical `PipelineRun`. *(On `/pipeline`, opens Component Details for Manager only; ignored for Researcher)*. | Queries and binds the **Last Successful Run** (`status=completed`). |
| `paper_id` | `/ask` | UUID | Locks the interrogation session to a specific `Paper`. | Opens `[Select paper first]` drawer showing top papers from active run. |
| `status` | `/pipeline` | String | Filters the runs table (`all`, `completed`, `running`, `failed`). | Defaults to `all`. |
| `screening_status` | `/papers` | String | Filters catalog rows (`passed`, `borderline`, `pending`, `rejected`, `all`). | Defaults to `passed`. |
| `sort` | `/papers` | String | Sort order (`signal`, `recent`, `dim:<key>`). | Defaults to `signal`. |

## 4. Frontend Verification Matrix

1. **Explicit Permalink Invariant**:
   - Navigating to `/papers/[id]?run_id=<historical_run_uuid>` must strictly fetch and display the `PaperMetric` corresponding to that run, even if newer completed runs exist.
2. **Missing `?run_id` Fallback Invariant**:
   - Navigating to `/papers/[id]` without `?run_id` must issue `GET /api/pipeline-runs/?status=completed&ordering=-started_at&limit=1`, obtain the latest completed run UUID, and transparently render its scorecard.
3. **Deep Linking from Briefings**:
   - Clicking any top paper card on `/briefing?run_id=<uuid>` must pass that exact run ID to `/papers/[id]?run_id=<uuid>` and `/ask?paper_id=[id]&run_id=<uuid>`.
4. **Pipeline Mutex Invariant**:
   - If `GET /api/pipeline-runs/?workspace_id=<id>&status=running` returns an active run, the `Run Pipeline` CTA must be disabled across all views.
